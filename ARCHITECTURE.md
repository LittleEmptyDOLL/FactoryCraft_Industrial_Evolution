# Architecture decisions — 0.25.1 (assembly/parts schema 4; fluid schema 2)

## 0.25 resource / recipe boundary

Native mB is the only fluid transaction unit; source Factorio values convert once at 1:10. Pipeline ownership/pressure algorithms remain 0.24.1. OilYield is exact geological percentage/cycle state, not an inventory; a ready canonical pumpjack commits paid, output-reserved crude creation and depletion together, retaining fractional work/output and source UUID. Generated-crude counters are explicit source terms in production ledgers.

3D solid patches use one deterministic generator-sampled anchor, a full smoothly irregular ellipsoid and center-relative richness. GeneratorTerrain caches immutable generator inputs and bounded anchor results; it can sample beyond the generation region without loading the anchor chunk. Only existing natural solids in the decorating chunk are written. Oil retains the frozen WG surface attachment. Existing finite resource owners remain non-ticking. No cross-chunk writes, artificial terrain, async server access or forced runtime chunks are added. Conservative structure-reference exclusion is documented.

Recipe selection uses a menu-scoped ResourceLocation protocol and readonly synced recipe metadata/research snapshots. Furnaces project actual RecipeManager smelting after FactoryCraft definitions; execution checks real matches/assemble, reserves the component-exact result and consumes one actual matching slot. Cache epochs and canonical definitions prevent changed recipes reusing old work. Processing/chemistry schemas permit up to sixteen counted ingredients; existing machines still have four physical input slots, so unsupported distinct-input recipes safely fail their full reservation. Labs still have four pack slots; future six-pack science must extend lab storage/menu/technology validation together. Furnaces share the smelting group; see FURNACES.md for burner ownership and paid fixed-point work.

Pre-0.25.1 FactoryCraft data is intentionally unsupported. Current-version physical ownership, exact partial work, guarded ports and separate-JVM checkpoints remain strict.

## Authority and persistence

All authoritative world access is on the server thread. Client renderers only extrapolate snapshots. Each block entity saves schema, inventory/carriers, phase/progress, selected/active recipe, fuel and energy as applicable. Vanilla block-entity update packets handle tracking clients; vanilla menus sync inventory and numeric data and validate recipe selection on the server. There is no client production simulation or per-carrier Entity.

An unloaded chunk pauses its machines. The power cache unregisters unloaded nodes. Belt scheduling discards unloaded references and reactivates loaded carriers. Neighbor lookups use `hasChunkAt`; production never force-loads a neighbor. The deliberate fixed-position persistence GameTest loads its fixture chunk, outside runtime simulation code.

Saving uses vanilla chunk persistence. Extraction into an inserter moves ownership from the source to the serialized hand. If a target disappears or fills, the hand keeps the item. Breaking a belt iterates until every carrier has been removed, avoiding index-shift loss. Breaking any inserter returns one portable device owning the held stack, fuel, energy and phase. Whole-machine demolition preserves resources in one portable controller item; parts never hold inventory copies.

## Circuit Network 2.1

`CircuitAttachment` composes canonical machine state with reciprocal UUID links, independent read/write color masks, structured programs and typed sparse int32 snapshots. It owns no inventory/fluid/FE. Parts resolve the owner through `CircuitAccess`; explicitly opted-in foreign containers use FactoryCraft SavedData, never injected foreign BE NBT. Four colors remain separate instances of ports in the **existing** `CircuitGraph`; maps replace scalar contributions without replacing topology caching/limits. `CircuitSimulation` stages changed device outputs, budgets sensor/program work and quarantines missing physical ends. Graph value callbacks queue evaluations rather than merging full maps recursively; topology loss closes direct gates immediately.

`SignalProgram` is registry/world-independent algebra (constant/each arithmetic/multi-condition decider with Else/selector/time). `CircuitDevices` reads real owners and issues guarded high-level commands; existing production/transfer transactions retain sole ownership. Recipe changes cannot discard paid progress; lab commands select the next available technology only for the bound team. `PipelineNetwork` is the single runtime source for pipeline contents, capabilities and circuit reads. The former `FluidAggregateIndex` runtime is removed; its snapshot value type is retained for callers. Different fluid components now form separate hydraulic segments.

`LogicMenu` accepts bounded typed configuration with menu identity/reach/protection/team checks. Initial state is included in native menu opening; later updates and acknowledgements are independent, so a live signal snapshot cannot erase an Apply acknowledgement. `CircuitVisuals` caches server-defined contact geometry and reciprocal wires; chunk unload evicts geometry. Client classes never evaluate production/circuit logic. See CIRCUITS.md for exact empty/wildcard/time, sample-hold, latency and limit semantics.

## Transactions

Recipes first reserve counts in a non-mutating per-slot plan, simulate the entire output, and verify available energy. A completed recipe revalidates inputs/output, then commits input extraction and output creation in one server-thread operation. Recipe ingredients are not consumed while progress is partial. A blocked output spends neither input nor energy. Removing inputs pauses progress; changing selection resets progress without consuming the inputs. Ordered overlapping predicates may conservatively reject a valid allocation but cannot spend one count twice.

Inserters first simulate source extraction and target insertion. Actual extracted contents are held persistently; target insertion returns an unaccepted remainder, which stays in the hand. Runtime assumes a conforming NeoForge `IItemHandler`: external mods that lie about returned counts violate that API's contract and cannot be made transactional from outside.

This provides conservation during ordinary server ticks, saves and chunk unloads. It is not a cross-chunk write-ahead journal guaranteeing atomic disk recovery after a process crash mid-region-file write.

## Belts

An ordinary belt has two bounded lanes of four physical carriers (each with a counted component-exact ItemStack); a splitter controller owns four lanes, addressed by two physical track positions. A segment has 96 integral coordinate units; spacing is 24 units. Nine server microsteps run inside each Minecraft tick (180 Hz); basic/fast/express carriers move 1/2/3 units per microstep. This preserves the existing 0.09375 / 0.1875 / 0.28125 blocks/tick speeds and gives exactly 15/30/45 items/s for two continuously supplied lanes in the independent kernel tests. Minecraft inventories and inserters operate at their own tick cadence; these kernel rates do not certify an entire in-game production line.

`BeltTransport` first projects all active lanes, then resolves cross-segment headway and destination reservations with an iterative worklist. Integral projections only decrease, bounding ordinary movement corrections to three units per carrier per microstep. It removes every outgoing carrier before inserting any incoming carrier, so a completely packed ring can move without requiring an artificial empty slot. Carriers retain their residual distance on transfer and are reused rather than allocated on each segment. At a speed transition the new speed applies on the next microstep (at most 1/180 s later); remaining spatial travel is retained.

Merges reserve the last quarter block before an entry. Competing sources wait before the junction and receive round-robin service; ordinary merging never moves a waiting item backwards. The physical 2×1 splitter has four lanes and alternates forward exits independently per lane, falling back to a free output. Routing includes already committed upstream approach reservations, rather than requiring the entire entry spacing before allowing an approach. This avoids wasting half the aggregate capacity with phase-shifted inputs while respecting quarter-block headway. Per-lane preferences persist. See SPLITTERS.md; filters, priorities and underground variants remain future work.

A per-level adapter caches loaded lane-to-lane links. Only placement, removal, load/unload and orientation changes refresh the affected block and four horizontal neighbors; there is no full-factory topology scan per tick. Facing invalidation occurs after `BlockEntity.setBlockState`, because Minecraft 1.21.1 calls `onPlace` before updating the existing block entity's state. Empty/jammed lanes sleep and are woken by inventory, position or connection changes. Neighbor lookups never force-load chunks.

Changes are batched once per block per game tick. Full block snapshots are sent on item-count changes and every four moving ticks. The client renderer extrapolates for up to four ticks and uses the complete block-length path instead of compressing it by 10%. Client prediction is visual, not an independent authoritative collision solver; curved junction paths and per-network delta packets remain open.

### Upgrade from 0.1.0

Belt schema 2 writes integral `Units` plus the legacy normalized `Position` field. The reader accepts schema 1 and copies the old splitter preference to both lanes when `AlternateRight` is absent. Actual 0.1.0 coordinates on the 1/32 grid convert exactly. Arbitrary edited legacy positions round to the nearest 1/96 block (maximum 1/192 block adjustment).

A legacy save or changed topology may already contain overlapping cross-block positions, which 0.1.0 allowed. On first simulation the solver conservatively shifts upstream carriers back to restore headway; no carrier is discarded. This one-time reconciliation can move an item back by up to a quarter block at a junction. Normal movement from a valid topology is forward only. Machine and inserter schema 1 data remain unchanged.

## Power — explicit copper edges (0.20.0)

`simulation.power.PowerTopology` retains the incremental, work-budgeted snapshot builder and round-robin distribution. Pole adjacency is now **only explicit reciprocal edges**, never overlapping supply areas or proximity. `PoleSpec` separates exact normal-quality Factorio 2.0 supply sizes/wire ranges from Minecraft heights. `PowerFootprint` tests positive horizontal rectangle intersection against the whole rotated machine foundation, with a separate configurable base-Y difference (default 4). Wire reach uses 3D foundation centers and the smaller range of both ends. See [ELECTRICITY.md](ELECTRICITY.md) for numbers, adaptations and controls.

Capture, explicit-edge union, component labels, device coverage and removal quarantine remain budgeted by `powerGraphWorkPerTick` (default 4096). The spatial hash uses fixed 32-block cells and bounded footprint queries; empty bucket probes and candidates both spend units. This is a logical work budget, not a wall-clock guarantee. Snapshots publish atomically; additions preserve previous valid routes, while removed poles/edges immediately quarantine their previous component. Independent components keep serving energy. Changed vertical reach invalidates old coverage. Prepared deliveries recheck route generation/liveness before FE commits.

`PowerGrid` adapts loaded controllers, including all existing sources/consumers, without changing recipe/fuel/work balance. Consumer lists remain shared per wire component; demand preparation visits at most 32 recipients and deduplicates overlapping memberships. Covered machines do not join distinct electrical networks. Network statistics count actual poles/sources/consumers/edges; no invented generation or consumption rating is displayed.

A pole is a schema-4 AssemblyOwner: one controller owns its UUID and `ElectricPole` schema-1 reciprocal position/UUID links, parts own no energy/network copies. A loaded-pole spatial index supplies placement-only auto connections. A reverse reference/chunk index reconciles saved endpoints without scanning all poles, respecting BE-tag/onLoad ordering. Unloaded or damaged structures cannot conduct. Chunk loading preserves manually removed edges; it never reruns proximity wiring. Destroy/portable teardown clears physical links and a replacement has a fresh identity. No normal path forces a chunk.

Original static geometry/collisions/attachment points share `pole_geometry.json`. Client-only renderers cache 16-segment sagging wire curves, draw each reciprocal edge once, and hide unavailable endpoints. Coverage overlays use exact squares and real-hit placement predicates, with locally cached proposed connections. Client code owns no production calculation. `/factorycraft power` reports the new topology; the pole menu shows saved/active connections and real network membership. Batteries, solar and nuclear remain future work.

## Canonical inspection and optional Jade (0.20.0)

`MachineInspection` resolves the controller from either a controller hit or identity-bound casing. FactoryCraft's own label uses the same path at both. Server readonly snapshots copy the sole owner's input/output/fuel stacks, native fluids, stored FE and available progress, with canonical/full-loaded/reach/permission checks. Parts persist no inspection copies and inspection never broadens physical automation capabilities.

Jade's standard NeoForge storage discovery uses the outward, unsided capability view. That view is not the full internal machine: especially fluid controllers intentionally deny unsided/nonport access. Optional Jade 15.10.6 integration requests an owner snapshot, replaces the name/icon and stock storage rows with one canonical rendering, including input and output. Its annotated entrypoint/API classes are isolated under `compatibility.jade`; common registration never links Jade classes. Both absent/present dedicated startup and real clients are tested. Existing physical fluid ports remain unchanged.

## Multiblock ownership and lifecycle — schema 4

MachineProfile dimensions, local layout origin, local controller and placement target are independent. `factorycraft/machine_layouts.json` defines per-profile controller and physical fluid descriptors; MachinePorts validates bounds, outward faces, channels and unambiguous cell/side pairs, caches normal/reflected definitions and resolved owner endpoint/neighbor positions, rebuilding only on facing/mirror changes, and applies the shared profile rotation. Default controllers are front-center; fluid-intensive profiles may choose base center. Geometry never owns resources.

AssemblyOwner/AssemblyAccess compose existing machine, thermal, fluid, research, beacon and splitter kernels. IndustrialAssembly caches full loaded identity/readiness. CasingBlockEntity stores only controller position, UUID and visual mirror metadata; a part is a fluid port only at descriptor-defined cells/faces. No structural item is registered or dropped. MachineFluidAccess views map INPUT/OUTPUT/BOTH to distinct owned cells, reject unsided/nonport access and recheck canonical ownership, UUID, complete readiness and fluid identity on every operation. Part unload/break invalidates capabilities before serialization. No neighbor chunk is force-loaded.

A single MachineItem forms the whole loaded footprint through native multi-place snapshots and rollback. PlacementPlan drives client and server with small-cell/medium-center/large-near-edge anchors and Shift center override. PlacementTarget rejects MISS, air and out-of-reach targets without reading unloaded cells. MachineInteraction records the clicked physical contact per server menu; proximity and owner UUID are checked for later operations, including module navigation.

Whole-machine demolition retires the formed identity before removing cells and produces at most one portable owner. StructureSupport strips assembly identity/links, preserving resources and a separate portable mirror setting. Native BlockItem merges saved state into the newly formed owner; MachineItem refreshes mirrored part metadata after that merge. Ordinary wrench mirrors fluid ports; Shift wrench dismantles. Layout/configuration changes invalidate topology only when they occur.

Schema 3/corner worlds are deliberately unsupported under the user's explicit 0.19 override. Existing worlds/checkpoints are archived untouched; schema-4 fixtures live in separate directories. No automatic migration, deletion, reseeding or refill occurs. Item/processing/boiling/chemistry kernels and codecs are retained. Earlier version-labelled sections below are historical design records; current coordinates/capability rules are those above and in MACHINE_DIMENSIONS.md / FLUIDS.md / PETROLEUM.md.

## Timing and performance evidence

All recipe durations are Minecraft ticks (20/s). Machine and inserter block tickers remain individual in this slice; active scheduling is implemented for belts, not all production. World mutation never runs on background threads.

The JUnit kernel benchmark now exercises 10000 complete two-lane segments (20000 lane nodes) for 100 Minecraft-equivalent ticks, with one carrier per lane in two closed rings. It verifies conservation and records CPU time without a hardware-dependent pass threshold. That kernel result excludes world costs. The separate `runBenchmarkServer` harness now exercises the actual 10000/1000/500 dedicated-world scenario; see BENCHMARKS.md for its deliberately finite inventory, no-client scope and measured results.

## Extension boundaries

`recipes` codecs support ordinary datapack replacement and `/reload`. `registry` owns NeoForge integration; `simulation` is independently testable; `production` adapts energy and menus; `energy` owns topology; `client` is client-only. Remaining trains, robots, pollution, combat and space require new packages and tests. No nonfunctional placeholder registrations represent these systems.

## Opt-in full factory profiling (0.2.2)

The Gradle `benchmarkServer` run uses a separate marked directory, flat void world and loopback port. FactoryBenchmark is inert unless its JVM property and marker checks match. The small SMOKE and independent-JVM checks pass locally; FULL/MIXED remain CI. Normal factory paths never gain chunk loading.

After warmup and JFR settling, ServerTickEvent.Pre/ Post capture 600 work durations (sleep is excluded). Census and report serialization are outside those durations. A pole is removed/replaced inside sampled ticks; real graph rebuild/distribution costs remain included. `FactoryTelemetry` adds opt-in counters to existing active work, not a whole-factory scan per tick. Dirty belt notifications prove every segment changed; actual completed recipes/deliveries prove producer/inserter liveness. Audits scan fixed fixture positions before/after sampling and during explicit restart verification. Raw iron/plates count as one unit, gears as two; items held by inserters are included. Stored FE plus delivered FE must equal final FE plus actual recipe spending. Generation still burns real coal.

`BenchmarkRecording` retains CPU/allocation/GC samples and Minecraft PacketSent/PacketReceived events. The diagnostic checkpoint additionally hashes canonical authoritative NBT before shutdown and verifies it before the next process's first tick. Compound keys are sorted; generated client snapshot/animation timestamps are excluded. After an exact match and resumed audit, verify atomically advances its checkpoint to the legitimately resumed state after flushing the world. It never accepts a mismatched hash by recomputing the expected value. This metadata is confined to the disposable fixture; normal game NBT schemas are unchanged.

## Historical fluid slice (0.3.0–0.23.0, superseded)

The following records the old solver for comparison. Runtime 0.24.0 uses the segment ownership/flow model below and in FLUIDS.md; old per-edge flow and full-cell ownership are no longer active.

`simulation.fluids` is Minecraft-independent: one canonical integer-mB cell, immutable fluid identity, reserved phased transfers and a cached active-edge FIFO graph. The world adapter under `fluids` keeps loaded adjacency and pump queues; no fluid block has a ticker. `FluidKey` owns a copied FluidStack and compares fluid plus data components. `FluidBlockEntity` exposes stable, lifecycle/orientation-checked NeoForge ports and one persisted cell. `GridConsumer` lets existing power snapshots supply either production machines or pumps without duplicating the grid.

Before mutation, the adapter checks the canonical LevelChunk/BE identity through ServerChunkCache.getChunkNow. Dirty changes mark the owned chunk unsaved immediately. ChunkEvent.Unload freezes/removes fluid nodes before ChunkMap serializes outgoing chunks; ordinary BE unload callbacks occur too late for this guarantee. Client reads use the client mirror, while all mutations require the server-owned loaded node.

New fluid NBT schema 1 uses the native FluidStack codec, retaining data components. Restored over-capacity volume remains drainable instead of being discarded. Harvested fluid blocks use vanilla BLOCK_ENTITY_DATA; freshly crafted empty blocks are stackable; harvested structures carry controller NBT. Assembly/parts use schema 3; native resource payloads stay unchanged. Menu volume/capacity/registry IDs are split into 16-bit words for vanilla data slots; BE snapshots are staggered to at most once per five ticks for fluid changes. This is full BE synchronization, not a measured delta protocol. FLUIDS.md specifies pressure math, pump order, energy and the distinction from Factorio 2.0.

## Thermal slice (0.4.0)

GridGenerator classifies the existing coal generator and new steam engine as sources in the same cached graph; GridConsumer behavior is retained. Engine output uses stored generated FE only. The 0.4.0 dedicated benchmark reload checks old authoritative hashes. ## Electric arms (0.15.0)

FactoryKind.inserter() registers four models through the existing BE/renderer. ArmCycle holds only paid phase math; InserterBlockEntity owns the single native ItemStack hand. FE is committed per movement/action quantum, with no idle/blocked billing. Cached source/target positions invalidate on facing changes; capabilities are queried at transfer opportunities, not on each paid swing tick. Filter changes affect only future pickups. A reentry guard prevents synchronous handler callbacks from running a second transfer.

Electric arms alone register as grid consumers and write Actuator schema 1. Mechanical serialized keys/timing remain unchanged. Native loaded/canonical/block-ticking/freeze guards protect tick and cached FE receivers; early ChunkEvent.Unload detaches before serialization. Electric block loot is empty because onRemove emits a single packed owner holding native hand components, FE, phase and configuration; the old owner is cleared/quarantined. Native menus use standard bounded buttons/data/ghost-slot packets and validate ordinary inventory clicks too. Arbitrary foreign handler callbacks and JVM crash journaling are not claimed atomic across files.

## Unified inserter adapter (0.21.0)

Six FactoryKind specs share ArmCycle's persisted 60-Hz paid units, ItemFilters' five type IDs and InserterCapacity's team/manual/item limits. InserterBlockEntity alone owns counted Hand, fuel/recovery and electrical/combustion buffers. Pickup/gather, outbound, partial drop and return stages preserve paid fractions; endpoint identity/canonical/ticking checks precede real capability operations, and reentrant packing waits until transfer ownership is resolved. GUIs never expose a mutable hand slot. Burner self-fuel bypasses cargo filters but transfers into its own saved fuel slot. Component-exact actual extraction results are retained; simulated counts are advisory, not a destructive promise. Arbitrary external handler crash-atomicity is outside this single-owner model.

BeltTransport and topology remain generic and unchanged: counted stacks extend only the world adapter and renderer. Native ItemStack NBT already preserves count/components; partial extraction shrinks a payload in place. Standard/Bulk deposit one item/carrier, Stack explicitly deposits up to the researched height. Telemetry distinguishes carrier count and weighted item totals, includes arm FE in the energy ledger, and does not add hot-loop work unless the benchmark is active. All electrical arms are real GridConsumers; finite examples now include fuel/connected poles or explicit finite test-only power where power generation is not the invariant under test.

Current hand schema is 3; old Actuator/filter-device data are not migrated. Assembly schema 4 and explicit electric-wire schema remain unchanged. The thirty archived integration methods have been adapted to current controllers/physical ports, finite power and actual hand timing and re-enter the mandatory GameTest set; archive provenance is retained in validation/assembly-v4-archive.md.


## Transport presentation and insertion, 0.23

`InserterPlacement` is the shared pure direction rule: perpendicular feed selects the far lane; reflection resolves only a parallel/antiparallel ambiguity. Each authoritative deposit addresses exactly one guarded physical track/input slot, using the existing single-carrier/stack APIs. `Reflected` is an additive flag in the existing arm schema; no fuel, energy, hand, paid-phase or carrier NBT format changes. The same server-validated native menu controls it, and hover rendering only samples the resulting physical geometry.

`TransportMesh` produces immutable cell-local faces/materials without Level/client dependencies. A monotonic height lookup bounds lift sampling to the current cell; a straight shaft slice uses one segment, an endpoint/twist at most sixteen. Closed hardware uses outward single-sided faces; ribbons retain required backfaces. The client loader rotates and bakes these faces into the ordinary solid chunk pass and caches at most 512 variants per baked model. Atlas frame updates animate tier surfaces independently of meshes. Model caches hold no ItemStack or authoritative world state. The server's route lengths, two lanes, ownership, headway, reservations and simulation scheduling are unchanged.

## Fluid segments (0.24.0)

`PipelineNetwork` owns one component-sensitive long pool per compatible loaded pipe/tank component. Passive edges are topology only. `FluidSimulation` adapts canonical loaded physical ports, chunk-indexed availability, pump work and persisted UUIDs. Each member serializes only a lazy capacity-prefix share; materialize before retiring/splitting/unloading/packing a pool. Chunk save arithmetic and independent-JVM restoration must conserve the exact sum. Ordinary intake/debit never walks members or recalculates connectivity; cached affected chunks are dirtied once per tick.

`BoundaryFluidCell` provides nonowning physical pressure quotas with separate input/output fractional credit, simulation and shared pump paid-tick guards. Canonical pool aliases cannot transfer to themselves. Machine recipe cells remain independent; assembly-4 BOTH/sided channels and finite stoichiometric commits remain intact. Segment extent is inclusive X/Z≤320; Y follows world limits. Pending reconstruction closes transfer and reports unknown circuits. Known overlong contents remain inspectable, not transferable. See FLUIDS.md for formulas, capacities, manual container adaptation and orderly-save versus crash-journal limits.

## Fluid performance invariants (0.24.1)

The pool/checkpoint ownership model and schema-2 NBT are unchanged. `Node.raw` is authoritative only without a published segment; attached raw bytes are inert, and every serialization path uses `owned()`. Budgeted traversal/sorting/staging may assign unpublished group references, but those references expose no pool capability. One valid flag publishes all prepared members together. Aborted staging retains exact raw owners and cleans references incrementally before retry. This avoids an unbounded member-publication loop without pretending staged totals are a second owner.

The deterministic pending index is an allocation-free indexed heap; bounded-degree neighbor arrays remain sorted, and per-build stamps replace visited identity maps. Only touches to the current build's discovered boundary cancel it. Already monotonic membership needs no sort; otherwise stable bottom-up merge moves use the work budget. Exact freeze remains eager at unload/structural ownership boundaries, with one prefix projection per member.

Known true leaves and redundant in-component edges have conservative local paths. Ambiguous multi-neighbor insertions retain the old canonical conflict choice. Local prefix/bounds updates remain atomic O(N), while incompatible/filter/overflow/overlong cases retain general rebuild quarantine. Cache preparation/detachment updates counted physical chunk references; pool changes dirty cached chunks and wake adjacent pumps without per-member sync fanout. See FLUIDS.md for invariants and BENCHMARKS.md for measured improvements and regressions.

Terrain ordering: new overworld decorating chunks retain a serialized 16×16 original-surface attachment (1024 bytes of height values before NBT compression, plus array/attachment overhead), even when no patch intersects that chunk. Sampling uses this frozen WG surface across FULL conversion/reload; it never substitutes decorated tree-top height for a completed neighbor. Not-yet-decorated supplied neighbors use their original WG map. Only the decorating chunk writes its snapshot. Pre-0.25 chunks without original terrain data are unsupported; custom biomes must include the resource features to participate. Prepared server diagnostics explicitly use their own primed test heightmaps.
