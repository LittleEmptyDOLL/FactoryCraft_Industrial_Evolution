# Проверка двумя игровыми клиентами — 0.13.0

Использованы два настоящих Minecraft 1.21.1 / NeoForge 21.1.252 и отдельный выделенный сервер. Это ручная GUI-проверка штатных меню/пакетов, а не имитация протокола. Сервер слушает только `127.0.0.1:25585`, offline-mode предназначен для двух синтетических локальных пользователей.

## Повторение

Нужны Java 21 и два графических дисплея. В этой среде использовались Xvfb/Mesa с программным OpenGL, не измерение FPS. Последовательно подготовьте классы/ресурсы и аргументы MDK:

```sh
./gradlew build writeClientLegacyClasspath writeServerLegacyClasspath prepareClientRun prepareServerRun
python tools/network_smoke.py server
# В двух других терминалах с доступным DISPLAY:
DISPLAY=:99 python tools/network_smoke.py client --name FactoryOne
DISPLAY=:100 python tools/network_smoke.py client --name FactoryTwo
```

`JAVA_HOME` должен указывать на JDK 21. Скрипт использует штатные подготовленные BootstrapLauncher/MDK-аргументы; все три Java-процесса запускаются отдельно. Не запускайте Gradle/перекомпиляцию, пока они используют общие классы. Подготовка с `-PsmokeWorld` отклоняется. Данные находятся только в помеченном `run-gametest/network-v0130`; обычные сохранения не открываются. Существующий мир продолжается, не пересоздаётся и не заполняется заново.

На новом стенде из консоли сервера:

```text
op FactoryOne
op FactoryTwo
execute positioned 100 80 100 run factorycraft sortingworks
tp FactoryOne 110.5 81 110.5 206.565 32.65
tp FactoryTwo 113.5 81 110.5 153.435 32.65
give FactoryOne minecraft:diamond 3
give FactoryTwo minecraft:emerald 4
gamemode survival FactoryOne
gamemode survival FactoryTwo
```

Команду строительства и выдачу образцов выполняют **один раз на новом стенде**, не при повторном открытии старого. Пример строит площадку и настоящую конечную линию: два сундука по 16 железа/16 меди, реальные манипуляторы/ленты/разделитель и два выходных сундука. Дождитесь штатной работы; `tick sprint 1500` лишь ускоряет наблюдение.

Разделитель находится в `(111,81,108)`, его правая часть `(112,81,108)`. Откройте с двух сторон. Первый игрок меняет вход на левый, второй выход на правый. Возьмите собственный образец курсором и почти одновременно нажмите ячейку фильтра. Последняя серверная запись побеждает; обе панели должны показать одинаковый тип. Закройте панели: по-прежнему ровно 3 алмаза/4 изумруда, никаких предметов из ghost-ячейки получить нельзя.

Для выгрузки безопасно переместите обоих на реальный пол этого плоского мира:

```text
gamemode creative FactoryOne
gamemode creative FactoryTwo
tp FactoryOne 1000 -63 1000
tp FactoryTwo 1003 -63 1000
execute unless loaded 111 81 108
```

Дождитесь успешной проверки, затем вернитесь на площадку теми же командами `tp`, откройте меню и проверьте сундуки/инвентари. Не телепортируйте survival-игроков на высоту 80 вдали от площадки: естественный пол здесь на -64.

Выполните `save-all flush`, затем `stop`. После полного сохранения остановите клиенты, запустите три новых JVM и снова подключитесь. Проверьте:

```text
list
data get block 111 81 108 Splitter
data get block 109 81 107 Items
data get block 114 81 107 Items
data get entity FactoryOne Inventory
data get entity FactoryTwo Inventory
execute if entity @e[type=minecraft:item]
```

## Фактический результат

Оба клиента одновременно редактировали фильтр в survival без расхода образцов. Последняя запись — изумруд; вход слева/выход справа. После расстояния, возврата и полного перезапуска сервер сохранил настройки, 32 сырого железа в левом сундуке и 32 сырой меди в правом, ровно 3 алмаза и 4 изумруда у игроков. Проверка ItemEntity после перезапуска не нашла сущностей. Клиенты показывают сохранённое меню на русском и английском. Штатные сохранение и остановка завершились успешно.

Первый дальний teleport при настройке стенда был ошибочно выполнен высоко над полом: игроки погибли от падения. Их исходные образцы были найдены в обычных выпавших предметах и подобраны в точном количестве, без повторной выдачи. После этого выгрузка повторена на безопасном полу. Мир/ошибка сохранены как диагностическое свидетельство.

Машиночитаемые наблюдения и хеши исходных журналов: [v0130-network-qa.json](docs/benchmarks/v0130-network-qa.json). Скриншоты: `docs/screenshots/splitter-*-0.13.0.png`.

Ограничения: loopback, два игрока, небольшая линия. Это не тест задержек WAN, онлайн-аутентификации, пропускной способности пакетов или FPS огромной фабрики. Стенд 10000/1000/500 проверяется отдельно без игроков; см. BENCHMARKS.md.
