# Real client checks — 0.25.1

Minecraft 1.21.1 / NeoForge 21.1.252 / Java 21.0.13, actual Linux client on Xvfb with software rendering, 854×480 viewport, render/simulation distance 5/5. Cloud desktop tools were unavailable; native X11 input and actual window captures were used under the cloud-desktop instructions. No optional viewer/Jade/FTB mods were installed for these local client runs; API compilation is separate, runtime profiles remain CI.

New worlds `FactoryCraft0251-QA` (flat void) and `FactoryCraft0251-Natural-QA` (normal noise, seed 3357260786188881509) were created from vanilla level metadata only, with fresh empty player inventory and no old chunks or FactoryCraft SavedData. Earlier worlds remain untouched.

* The real finite-input showroom renders distinct Stone/Steel/Electric bodies. Stone and Steel consume actual coal, show stored burn ticks and finish plates; GUI shows 64/32 ticks and solid fuel, without a module button. Electric shows 32 ticks, 24 FE/t and exactly two module slots. Its depleted FE buffer pauses partial work; no coal feeds it. [Stone](screenshots/stone-gui.png), [Steel](screenshots/steel-gui.png), [Electric](screenshots/electric-gui.png), [modules](screenshots/electric-modules.png), [bodies](screenshots/furnaces-world2.png).
* The shared recipe selector contains FactoryCraft plates/steel/stone bricks and actual vanilla smelting recipes. [Browser](screenshots/stone-recipes.png).
* Actual Feature calls on prepared finite stone intersect flat ground, a slope and both cliff orientations, preserving deliberately placed water/air/gold. The exposed body stops around its fixed center instead of draping down to lower ground. Higher terrain exposes the upper hemisphere. These are diagnostic prepared terrain scenes, not screenshots claimed to be naturally generated. [Flat](screenshots/flat.png), [slope](screenshots/slope.png), [lower cliff](screenshots/cliff.png), [upper cliff](screenshots/upper-cliff.png). The camera for the new final upper-cliff scene was manually matched during QA and corrected in ResourceShowcase so the command does not place it inside the higher plateau.
* The untouched normal-noise world naturally generates finite ore in solid seabed while preserving water/kelp/air. At (904,56,72), actual resource BE data reports Initialized=1, Remaining=2763. [Natural scene](screenshots/natural-ore.png). The existing local common-config **spacing override is six**, not the shipped default sixteen; radii/stocks/vertical bounds remain default. The saved read-only census contains 40199 ore BEs / 87435118 units and eight oil points; see [JSON](natural-world-save.json). No stone terrain was constructed in this world.
* Both worlds report normal `All dimensions are saved` after leaving through the menu; the client exits normally. Current-format stock/fuel/fractional-work persistence across separate JVMs is checked by the native suite, not inferred from these screenshots.

Audio hardware/OpenAL is unavailable and Mojang public-key requests fail in this offline development environment; neither blocked graphics, local gameplay nor save completion. No real two-player QA, custom world-generator compatibility, optional-mod runtime or sustained natural chunk-throughput claim is made.
