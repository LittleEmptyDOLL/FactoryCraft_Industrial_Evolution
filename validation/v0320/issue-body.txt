## 2. Signals and real block ownership (the essential foundation)

- Define **logical rail blocks** split by ordinary and chain signals at **directed edge-point positions**, even in the interior of one physically saved spline without mutating its original saved UUID/paid material ledger. Blocks are connected unsignaled rail regions; multiple physical rail edges can form one logical block, and a train straddling several blocks occupies **all** of them until its last wagon clears. Enforce the Factorio rule that one physical block cannot belong to two incompatible trains at once.
- Implement **regular signals**: green free, yellow approaching/reserved, red occupied/conflicted. **Chain signals**: green when all relevant exits open, red when none accessible, blue when only a subset of route-dependent exits are available, yellow for reserved passage; the chosen train route determines whether the blue chain may be traversed. Chains must reserve a safe exit beyond a junction **before allowing entry**, not allow trains to stand in a crossing and deadlock.
- Block topology must consider **turnout shared conflict geometry** and `SpatialReservations`, including wagons spanning split points; unrelated vertically separated tracks with verified clearance must remain separate. At-grade geometric crossings currently disallowed by the foundation remain disallowed, not mysteriously connected. Same-level conflict shapes conservatively assigned to affected logical blocks as required.
- Only actual right-of-track valid signals govern automatic movement in that direction; a pair of opposite signals makes bidirectional use possible. Detect invalid/unattached signals and show an obvious invalid/blinking state. Placement hints should highlight block boundaries, linked counterpart positions and colored rail-block segments like Factorio.
- Preserve native circuit `force red` and signal-reading semantics. Manual trains **in Factorio may ignore signal colors**, but do not relax FactoryCraft's existing hard train-to-train collision/swept conservation protections as an unsafe side effect: manual input bypasses *signal-based control*, not physical safe reservation. Document this Minecraft safety adaptation.
- Atomic block acquisition/release and signal transitions per server tick; no window where two trains can reserve the same block or same junction. Rebuild only affected neighboring blocks after track/signal edit; no global O(E) rebuild per tick. Rail/signal removal under an existing consist must fail closed and not erase claims.

## 3. Train stop objects, names, limits and priorities

- Stops have user-defined **name, train color, server-owned UUID**, actual directed edge/position, priority **0–255 (default 50)**, optional train limit, enabled state and pending train count. Multiple stops with identical names are meaningful independent destinations, **not aliases of one physical station**.
- When dispatching to several enabled same-name stations, respect **highest applicable priority then path cost**, with the correct origin-station dispatch priority where multiple waiting trains compete. Reserve a stop slot **once** before dispatch, count approaching + docked trains, and release on legitimate departure/reroute/retirement; never duplicate slots on restart/reload/stop rename.
- Deactivated stop or train limit=0 causes **Destination full**, not silently skipping a schedule entry. An already committed en-route train may finish at its stop if that stop gets disabled or its limit decreases, matching Factorio 2.0+. Differentiate unavailable name (**No path**) from enabled but saturated/disabled (**Destination full**). Deleting/renaming a stop must deterministically invalidate affected commitments and trigger safe repath.
- Station arrival: validate **direction, leading locomotive and actual train length**, dynamically brake to target metric pose without overshoot, maintain full-train occupancy, then wait according to schedule. Only stopped wagons permit existing real inserter/pump interactions. No phantom/offline loading or fuel. 50000 Factorio fluid units =500000mB existing conversion.
- GUI: name/color/limit/priority, trains on the way, currently docked train, valid arrival direction, wagon footprint ghost, circuit controls; invalid path/destination full indicators. Prefer Factorio 2.1 stop/locomotive GUI layout adapted to Minecraft, not a new unrelated station minigame. Preserve existing manual cargo/fuel menus.

## 4. Automatic mode and pathfinding

- Add **Manual ↔ Automatic** train control state to canonical `TrainData`; automatic motion uses the same 0.31.x source traction, reverse locomotives, fuel, 3×60Hz substeps, swept-body checks and chunk quarantine. A driver exiting does **not** stop a train in Automatic mode; player takeover/manual mode must safely cancel/reconcile pending automatic reservations, never teleport, double-debit or bypass braking.
- Directed graph pathfinding (Dijkstra/A* with bounded work/cache) on actual `RailGraph` and **metric segment lengths** incl. 16 heading families, heights and current switches. Enforce legal direction (including facing locomotive and stop/signal side), radii, turnout alternatives, no mythical U-turn without physical turning loop or reverse locomotive. Resolved route must install actual `TrainPath` directed legs with correct fractional begin/end offsets; preserve historical legs under all bogies and validated rail occupancy.
- Follow Factorio 2.1 documented route penalties where applicable: physical distance, occupied/blocked blocks, red circuit signals, stops on path (not target), waiting manual trains, etc. See `Railway/Train_path_finding`. **Do not call invented weights source exact.** Event-driven repath on rail edits, signal changes, invalid destinations, limit/priority changes, braking at a blocked signal and schedule edits; re-evaluate at chain-signal wait intervals rather than scan all trains and whole rail graph every tick. Cached routes must include rail graph topology revision and signal/stop revisions.
- Train mode/status visibly differentiates automatic cruising, braking, waiting at signal, waiting at station, **No path**, **Destination full**, no fuel and unloaded (fail-closed). Strong diagnostic/debug overlays: highlighted intended route, occupied/reserved blocks, train's braking distance, offending signal and reason for refusal.
- Multitrain safety: two-way single track with bypass; opposing entries; chain signal before shared junction; alternating branch of parallel loop; multi-car consists longer than a single block; blocked destination; signals at different heights; player/manual train; deleted rail/signal/stop mid-route; speed up to259.2km/h. Stop ahead of red respecting actual stopping distance without causing false emergency full stops. Reserve and release all intervals and logical blocks as last wagon clears.

## 5. Schedule editor, conditions and Space Age 2.1 control features

Build the **Factorio schedule model correctly**, not a single "go to XYZ" button:
- Ordered stops, loop back after final stop; entries use **station names**, not just UUID targets. Add/remove/reorder; manual "go to stop", temporary route and cancellation without permanently altering train group schedule.
- Wait condition types from the **Factorio 2.1 Railway wiki**: time passed; inactivity after last actual cargo transfer; full/empty/has cargo; filtered item count; filtered fluid count; all/any locomotive fuel; full fuel; passenger present/absent; station full/not full; circuit condition. No condition means pass through. Respect item filters/components, train-wide totals, fuel excluded from cargo, Factorio 1:10 fluid unit scaling, and **AND groups separated by OR (disjunctive normal form)**, not naive left-to-right.
- **Train groups:** named shared persistent schedules, membership, edit propagation to all members, no loss of individual temporary stops or resources when joining/leaving. Permission/ownership checks and safe migration on train coupling/splitting/recovery.
- **Schedule interrupts (Factorio 2.0+/Space Age):** ordered condition + temporary target list, support refueling detour, destination full/no-path, at/not-at station and cargo/circuit checks, then return to original schedule. Store shared named interrupts and scoped train/group references, not copies that silently drift. Support matching wildcard types **Any item / Any fluid / Any fuel / Any signal**, replacing target-station name/conditions with the actual resolved typed signal, with predictable failure if target station does not exist; do not invent missing mod content or allow wildcard injection into arbitrary untrusted commands. Preserve non-recursive/controlled interrupt behavior and no unintended infinite rerouting.
- **Priority dispatch** for waiting origins, real circuit-triggered behavior and station color when supported; evaluate 2.1 source rules, document any absent optional UI conveniences (map click temporary stops, remote driving, group auto-color) rather than claiming full feature parity.

If all advanced editor/group/interrupt features cannot responsibly be implemented and tested in a single Codex job, deliver a **genuinely functioning basic automated rail system first** and explicitly retain the advanced acceptance items in this SAME issue for a subsequent run. **Do not mark 0.32 complete** if only stops/signals or only basic schedules exist. No invented placeholder "interrupt" UI that has no working behavior.
